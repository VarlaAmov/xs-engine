# Repository instructions

- Read `README.md`, `docs/ARCHITECTURE.md` and `docs/EXPERIMENTS.md` before changing the engine.
- Before repeating an experiment, identify its existing journal entry and explain what changed.
- Update the journal with the baseline, outcome, limitations and decision after performance work.
- Distinguish measured results, estimates and untested ideas. Do not turn a failed implementation into a universal impossibility claim.
- Keep public examples independent of a particular deployment. Do not add personal identifiers, private addresses, local runbooks or conversation logs.
- Preserve upstream license notices and reference test fixtures.
- Run checks appropriate to the change. Full-model GPU tests require an exclusive test environment.
- Put changes on `develop` and propose a PR to `main`; do not merge without the maintainer's review.
